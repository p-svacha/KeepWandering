- item tag expansion
  - tags are used solely for item slots, so commit to that and use more tags to describe HOW items can be used (i.e. scavenging, combat, fortifying)
  - traditional tags like i.e. "food", "tool" still need to exist, as they can still be used for more general item slots
  - since tags aren't communicated to the player, it's no problem to have many/specific/overlapping/technical tags, as long as they make sense from a design perspective
  - allow items to have optional "tag value modifiers", that can be used if an item is particularly good or bad at a certain tag
  - if this modifier is present, the difficulty modifier of slots will be adjusted by that value if filled with this item
  - i.e. a bone can be used for combat, but its not very good at it. so it does have the combat tag, but with -5 modifier. so if its dragged into a combat slot with diffiuculty reduction of 20, the effective difficulty reduction would be 15.
  - or i.e. a flashlight can be used for scavenging, and is very good at it, so it has a +5 modifier for the scavenging tag. so if its dragged into a scavenging slot with difficulty reduction of 10, the effective difficulty reduction would be 15.
  - difficulty reduction overrides for specific items can still be done in a slot just as before, still with 1st priority
  - add new validations for item defs and item slots for the new system
  - main goal of this is to allow for more variety in items, and to make it easier to create high value items without having to change every slot in every encounter option
  - also creates new strategic tradeoffs (should i use this item with a -5 combat modifier, or should i save it for scavenging where it has a +5 bonus?)
  - reflect all changes in the GDD
